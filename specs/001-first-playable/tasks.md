# Tasks: AS You Were — First Playable Version

**Input**: Design documents from `/specs/001-first-playable/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md

**Tests**: Required. Constitution principle I and the plan require automated checks that compare
the evaluator's output **and feedback text** with hand-verified fixtures. Within each story, write
tests first and confirm they fail before implementing.

**Organization**: Phase 3 (US1) builds **one complete round, Round 2.1, end to end**: rule engine,
feedback text, content data and validation, session state, UI, and its automated and manual
verification. Later phases extend the same code to all six rounds without a new scoring path
(principle VI).

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: Which user story this task belongs to (US1, US2, US3)
- Paths are relative to the repository root (single static project, per plan.md)

## Path Conventions

Static web project at the repository root: `index.html`, `style.css`, `main.js`, `engine/`, `ui/`,
`data/`, `tests/`. No build step. Preview with `python3 -m http.server 8000`.

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)** → **Foundational (Phase 2)** → **US1 (Phase 3)** → **US2 (Phase 4)** → **US3 (Phase 5)** → **Polish (Phase 6)**
- US2 extends the files built in US1 (one engine, one set of screens), so it starts after the US1 checkpoint.
- US3 can start after US1 for T031–T033 if staffed separately, but T034 verifies the full game and needs US2.

### Within Each Story

- Tests first (they must fail), then engine, then data and validation, then state, then UI, then the verification task.
- T012 (rules) blocks T013 (feedback uses the ladder) and T015 (validation uses the rules).
- T026 (confirm the level summary) blocks T028.

### Parallel Opportunities

- Setup: T002 and T003.
- US1 tests: T007–T011 are in different files.
- US2 tests: T021–T024 are in different files.
- US3: T032 and T033.
- Polish: T035 and T036.

## Implementation Strategy

### MVP first: one complete round

1. Phases 1–2: skeleton, failing test runner, fixture format, loader.
2. Phase 3: Round 2.1 end to end, including its automated tests and recorded manual check (T020).
3. **Stop and validate.** If time is short, ship this with the remaining scope listed as not done
   (constitution VII); never cut its fixtures or feedback checks to add polish.

### Incremental delivery

1. US2 adds the other five rounds, help, and summaries using the same engine (data change plus
   checks, principle VI).
2. US3 completes access and motion.
3. Polish packages and re-verifies.
